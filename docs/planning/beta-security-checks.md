## Product bugs found

1. **The host runs a Windows `.cmd`/`.bat` verify command when it is named explicitly.**
   - **Where:** `agora-host/src/verify.ts:45-47` (`resolveExecutable` returns an absolute name, or one with a path separator, as-is, with no extension check), `verify.ts:22` (`VERIFY_COMMAND` allows `.` and `/`, so `./scripts/check.cmd` is a valid command), and the Windows job wrapper in `runVerify`, which starts the file with `Process.Start`. Windows runs `.cmd` and `.bat` through `cmd.exe`.
   - **Expected:** plan §6.2 says Windows `.cmd` is "refused by … host", and `docs/project-context.md:61` says Windows can't start `.cmd` shims without a shell.
   - **Actual:** `runVerify(['<tmp>/check.cmd'], …)` runs the batch file. Its marker file is written and the result is `passed: true`.
   - **Repro:** on Windows, `cd agora-host && npx vitest run test/verify.test.ts -t "named explicitly"`. The test is `agora-host/test/verify.test.ts:92`.
   - **Severity:** low. The host owner must list the command in `verify.commands`, and the allowed characters exclude `& | ^ %`. But a `./….cmd` path resolves inside the worktree, which the agent can write, so the agent could rewrite what the host runs through `cmd.exe`. A bare `npm` is correctly not resolved to `npm.cmd` (`verify.test.ts:76` passes).

2. **Once the tts daily limit is reached, a message that was already voiced is refused instead of served from the cache.**
   - **Where:** `src/routes/voice.ts:312-320`. `voiceRoute()` runs the budget check (`src/ai/routing.ts:108-133`) before the cache lookup at :318-320.
   - **Expected:** plan §6.4 says "cache serves repeats without counting". A cached repeat costs no provider call and isn't counted (that part passes), so it should still be served after the limit.
   - **Actual:** `429 {"error":"Daily request limit reached for \"tts\" (N/day)","code":"budget_exceeded"}` for the cached message.
   - **Repro:** `npx vitest run test/integration/voice.integration.test.ts -t "already voiced"`. The test is `test/integration/voice.integration.test.ts:413`.
   - **Severity:** low, and it depends on reading the Pass text. If "cache serves repeats" means only that repeats don't count, this is not a bug and the test should be dropped. Decide when filing.
